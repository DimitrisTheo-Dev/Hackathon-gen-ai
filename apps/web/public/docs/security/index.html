Access and approval

Preparation can be automatic. Publication needs authority.

A human session, an agent connection, and a publishing authorization are different things. Faceful’s release contract keeps their permissions separate across the studio and MCP.

Tested, not certified

Automated tests and a live check against the Supabase project cover the denials listed at the end of this page. That is evidence for those cases, not a security certification. Publishing has not been exercised against a real provider, because none is connected. A readable docs page or a scanner score proves neither tenant isolation nor safe publishing.

Workspace access

The engine derives the principal and the workspace from the verified credential, never from actor IDs or flags in the request body. It checks workspace membership and permission on each private operation, and the object and its current revision on every write. An ID from another workspace is reported as not found. The browser cannot write workflow state, approvals, membership roles or credentials directly: database row-level security lets members read only their own workspace.

Agent connection scopes

An agent credential carries a subset of six permissions: campaign:read, content:edit, render:write, schedule:prepare, billing:read and billing:checkout. Agents are never given schedule:approve, schedule:commit, billing:manage or connections:manage. The machine-readable permission definitions report them as enforced only where the engine is configured; reading them grants nothing, and they are not OAuth scopes. A tool being visible does not grant authority to use it.

A workspace token is created by a signed-in owner or admin in the studio. It is revealed once, stored only as a SHA-256 digest, bound to one workspace, expires within 90 days and can be revoked. An agent connected through OAuth acts for the member who approved it on the consent page, with that member’s role narrowed to the same six permissions; that path is implemented but has not been trialled end to end. Never use a Supabase key, browser session cookie, or publishing provider token as an MCP credential.

Review-first publishing

The default flow prepares an immutable manifest containing the final asset identifiers/hashes, exact copy, accounts, visibility, disclosures, and times. A human reviews that exact manifest. A changed item cannot inherit the approval of an older version. A client-supplied approved: true is not approval evidence, and an agent that asks to approve receives approval_required with a review link.

Unattended runs are not available

Authorizing future publication without reviewing each video is not part of this build. A request for a run grant is refused, and every schedule is approved by a signed-in member. No publishing destination is connected, so an approval cannot currently lead to a post.

Revocation and cancellation

Revoking a connection blocks new authenticated calls. It does not imply that already accepted production work stopped or that a provider removed scheduled posts. Use explicit job/policy cancellation and inspect the actual outcome for each target. Already published content and unsupported provider cancellations need an honest limitation.

Untrusted sources and private assets

Imported text is evidence, not instructions. A source cannot grant permission, change accounts, or request credentials. Source URLs are stored as references and are not fetched. Rendered media sits in private storage and is played through short-lived signed links.

What has been tested

Automated tests exercise wrong-workspace access, missing permission, expired or revoked tokens, forged schedule hashes, stale schedules, credit exhaustion and replayed operations against the engine with an in-memory store. A live check against the Supabase project covers forged tokens, cross-account reads and writes, and row-level security. Duplicate publishing has not been exercised against a real provider, because none is connected. Keep these results separate from a public discoverability audit.

Protocol references: MCP authorization and MCP security guidance.
