Formats and limits

Only offer what the connected services can deliver.

The first complete journey targets three distinct avatar videos, each with its own script, platform copy, render revision, and schedule targets. Live availability must come from the backend’s context response.

Provider verification pending

No live Humanlike render or social publishing receipt has been verified in this studio build. Drafting, versions and schedule review work where the engine is configured; the combinations below are the implementation target, not a claim that these channels are connected or currently available.

Check context before acting

The studio reads the workspace context from the engine, and an agent reads the same facts with list_avatars, list_projects and get_billing_status: authorized presenters and their languages, whether rendering is available and why not, remaining render credits, and the state of each item. Fixture mode is identified as such. A disabled action is not permission to bypass the service.

Limits that can be enforced

Render credits, a per-workspace concurrency limit, item counts and token expiry are enforced on the server. A workspace starts with a small starter allowance set by the deployment (three credits by default), and each render holds one credit by default. The live numbers come from the workspace context and billing status; none is an unlimited allowance. A three-video plan can mean nine posts when all three videos target all three channels.

The credit held for a render is returned if the job fails, is cancelled or is never picked up, and a revision that already has a verified video is not rendered again. Without an attached renderer, a render request is refused and holds nothing. No price, dollar budget, sponsor allowance or revenue forecast is represented here; billing, where configured, is Stripe sandbox only.

Production and publishing are different states

Draft
A persistent plan or content item exists.
Queued / running
The service accepted work and has a stable job ID. No finished video is implied.
Ready for review
The reviewed current revision has final media. Playback alone does not authorize publication.
Provider accepted
The publisher acknowledged the scheduled submission for that target.
Published
Provider evidence identifies a delivered post, with its ID or link.
Unknown outcome
The result needs reconciliation. Do not blindly resubmit.

Time and versions

Store schedule instants in UTC and retain the workspace’s IANA timezone for display. The requested time and observed publication time are separate: platform processing can delay delivery. An expired scheduled time must not become “publish now.”

Script, avatar, or visual changes invalidate the render. Platform copy changes invalidate schedule approval while potentially reusing the video. The exported video must include the reviewed captions and branding; an editor overlay alone is not the final composition.
