Connect your agent

Bring the agent you already use.

Codex CLI and Claude Code are the two clients that have been tried. This page covers the workspace-token path. OAuth sign-in is implemented but not yet trialled; it is described on the MCP page.

Check this deployment first

These steps work where integration status reports engine.mcp: true. Elsewhere /mcp answers 503 and they cannot complete. Never use a Supabase key or a publisher credential as an MCP token. No two-minute setup claim has been measured.

Create a workspace token

  1. Sign in to the studio as a workspace owner or admin and open Connect your agent.
  2. Create a named workspace token with only the permissions the agent needs and an expiry of at most 90 days. It is shown once; Faceful stores only its SHA-256 digest.
  3. Keep the token in your secret manager or shell environment, out of prompts, URLs, recordings and git.
export FACEFUL_TOKEN='paste the token here'

The examples use https://faceful.dtheo.dev/mcp. If you open the studio on a different origin, use that origin’s /mcp.

Codex CLI

codex mcp add faceful \
  --url https://faceful.dtheo.dev/mcp \
  --bearer-token-env-var FACEFUL_TOKEN

For manual configuration, the same entry in your Codex configuration is:

[mcp_servers.faceful]
url = "https://faceful.dtheo.dev/mcp"
bearer_token_env_var = "FACEFUL_TOKEN"

The token field names an environment variable; the token itself never goes in the file. Reference: official Codex MCP configuration.

Claude Code

Merge the following into a trusted project’s .mcp.json; do not overwrite existing server entries. The token stays in the environment.

{
  "mcpServers": {
    "faceful": {
      "type": "http",
      "url": "https://faceful.dtheo.dev/mcp",
      "headers": {
        "Authorization": "Bearer ${FACEFUL_TOKEN}"
      }
    }
  }
}

Start Claude Code from the shell that has FACEFUL_TOKEN, review the project server trust prompt, and inspect /mcp. Reference: official Claude Code MCP setup.

Confirm the connection

Ask the agent to call list_projects and get_billing_status. A real connection returns your workspace’s projects and credit balance, and the studio’s connection list records when the token was last used. Copying a command or seeing a server in local configuration is not a successful connection.

List my Faceful projects and read my plan status and render credits.
Tell me which presenters are available and whether rendering is connected.
Do not create or change anything.

First request

Drafting is free, so start there. Use concrete dates, and settle the timezone before asking for posting times.

Using the brief I gave you, create a Faceful project with three distinct
15-second scripts. Then propose posting times for 16, 18 and 20 November 2026
at 09:00 Europe/Athens and show me the blockers. Do not render anything.

Posting times are drafts. A signed-in member approves the exact schedule in the studio, and no publishing destination is connected yet, so nothing is posted.

What has been tried

Codex CLI 0.169.0 and Claude Code 2.1.325 connected with a workspace token against a local engine server backed by the real Supabase project, with the configuration passed per run. A trial against the deployed endpoint and an OAuth sign-in have not been recorded yet. Other MCP clients are untested: Streamable HTTP support alone does not establish authentication or workflow compatibility.
