Faceful API documentation

Discover current capabilities and public guidance with typed, credential-free reads.

The public discovery API gives agents an honest starting point: this deployment’s integration status, agent permission definitions and documentation. It cannot read private campaigns, issue credentials, create videos or publish posts.

  • Live Public reads, no credentials
Public reads need no credentials. Private operations are separate.

The OpenAPI 3.1.1 document describes only these public routes. The authenticated domain API under /v1 and the MCP endpoint at /mcp require authorization and exist only where the engine is configured. Check engine.campaignApi and engine.mcp in the status response first; a deployment without engine credentials answers those paths with 503.

Make the first call

These reads require no token. Never send Supabase keys, browser cookies or downstream provider tokens to the public API.

Implemented operations

Public API operations. Each supports GET and HEAD.
PathResult
GET/api/public/statusWhat this deployment has configured (campaign API, workspace tokens, MCP endpoint, rendering, billing, Creative Director mode), plain-language blockers and useful links. Derived from server configuration on each request.
GET/api/public/permissionsThe permissions an agent credential can carry and the ones reserved for signed-in people. Reported as enforced only where the engine is configured. Reading them grants nothing, and they are not OAuth metadata.
GET/api/public/docsFixed documentation index with supported slugs and canonical URLs.
GET/api/public/docs/{slug}One document as Markdown content inside typed JSON.

Each operation has a unique operation ID, a description, response schemas and concrete examples in the specification. There is no arbitrary URL-fetch operation. HEAD has the same status and headers as GET, without a response body.

Versioning and deprecation

Send X-API-Version: 1 to pin major version 1. Omission defaults to 1. JSON responses identify the served version and include Vary: X-API-Version. An unsupported version returns HTTP 400 with unsupported_api_version. The repository CLI pins version 1.

Additive fields may be introduced within a major version; incompatible changes require a new version. Before retiring a version, we will publish its migration path here and emit the Deprecation header and a Link with rel=deprecation. A Sunset header will identify a confirmed retirement date. No version is currently deprecated and no sunset is announced, so those headers are not emitted.

Errors and recovery

Unknown public routes return HTTP 404. Unsupported methods on known routes return HTTP 405 and Allow: GET, HEAD. Both use RFC 9457 application/problem+json with a stable code and actionable resolution.

Limits and caching

The documentation index is finite and needs no pagination. Successful public reads may be cached for 60 seconds; errors are not cached. Hosting limits remain subject to the deployment platform. No numeric production quota or dollar budget is advertised before it is enforced by the engine. Avoid aggressive polling and honor any platform retry response.

Next step

Use the repository CLI for public discovery and local plan validation. Read Use Faceful with your AI agent before setting up a client. A valid local plan is not an accepted render or an authorized schedule.
