# Castroom: three-minute demonstration

Prepared 14 November 2026. This is a rehearsal script, not evidence that the live flow has passed. Replace bracketed observations with measured values only. If a gate is unavailable, disclose it before showing a fixture or recording.

## 0:00–0:20 — The operator and the job

“A company already has an AI agent. But a prompt alone does not give that agent the company’s approved presenter, brand context, finished assets, permission to publish, or a durable production service. Castroom gives the agent those resources, and gives the operator a studio to see and control the work.”

Show the campaign canvas. Identify the selected workspace and whether this is live or a development fixture.

## 0:20–0:55 — One brief, three content items

In a fresh, authenticated Codex or Claude Code session, first call `studio_get_context`. Then ask for three distinct avatar-video drafts from the supplied brief, with separate platform copy and the agreed exact schedule targets.

“This demo uses Quintessential’s published BeWell case study as source material. It is our independent demonstration, not an endorsement or partnership.”

Show stable campaign and job IDs arriving in the studio. Do not narrate simulated percentages, agent thought transcripts, or provider success before a receipt exists.

## 0:55–1:25 — A human changes the work

Select one item in the right-hand editor. Play a real final Humanlike output with audio if available; otherwise explicitly say the rendering integration is unavailable and show the disclosed fallback.

Change the script’s opening, save, and show the revision increment and stale-render state. Ask the agent to read the campaign again and quote the new opening. Regenerate only the affected item.

“The studio and the agent see the same revision. Editing here changes what the agent reads next.”

## 1:25–1:55 — Brand context has consequences

Demonstrate one unsupported claim from a controlled test input. Example: an assertion that BeWell “guarantees better health” is not established by an app-development case study. Show the evidence link and a factual replacement, such as a description of finding sessions and navigating the festival.

“The source informs the work. It cannot give the agent permission to publish or override the owner’s rules.”

Only call this an automated brand check if the live check actually ran. A fixture warning must remain labeled.

## 1:55–2:30 — Review, authorization, receipts

Open the exact schedule manifest. Show final video, copy, selected account, AI disclosure, visibility, and Athens display time for each destination. Approve that immutable manifest through the authenticated owner interface.

Show provider acceptance independently for Instagram, TikTok, and YouTube. If a destination fails, retain successful destinations and show the precise recovery. Show “published” only when there is actual provider evidence and a real post ID/link.

“A queued job, an accepted schedule, and a published post are different outcomes. This screen tells you which one happened.”

Report only measured facts: **[completed videos]**, **[accepted channel jobs]**, **[published posts]**, **[recorded human interventions]**, **[wall-clock elapsed]**, and **[active operator time, if measured]**. If no manual baseline was measured, do not claim time saved.

## 2:30–3:00 — Next week

“Our first customer hypothesis is an agency serving multiple client brands: a subscription plus metered production, with direct individual access too. Next week we want to test that workflow with operators, validate the real rendering and publishing costs, and measure the manual baseline. Revenue and margin are hypotheses today.”

Close with the actual live/preview URL and tested client names. Do not call untested hosts compatible just because they speak MCP.
